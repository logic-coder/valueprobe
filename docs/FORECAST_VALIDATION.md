# 预测检验工具

这是给维护者复核口径用的内部工具，不是面向普通投资者的功能，也不构成改官方增速或折现率的许可证。不要把它做成站点上的研究工作台，也不要把结果当作官方发布值。不要把检验数字或「领先 / 不领先」写进产品文案。

## 怎么跑

在仓库根目录：

```bash
npm run research:forecast            # 按官方发布路径跑因子实验，写入 scripts/research/forecast-validation-official.json
npm run research:forecast -- --check # 核对已提交的官方因子结果与 2026-11-22 研究跑数
npm run research:forecast -- --historical
npm run research:forecast -- --historical --check
```

`npm run research:check` 会包含上述 `--check`。默认输入是已冻结的 2006-03-15 入场现金面板 `scripts/research/cash-path-inputs.json`。扩大样本的面板放在 `scripts/research/forecast-validation-panels/`，输出一律放在 `scripts/research/`，不进入 `public/`，也不会出现在方法页。

## 现行官方检验：与发布路径对齐的因子实验

`scripts/research/forecast-validation-official.json` 是维护者因子实验，不是通用验收，也不是改官方规则的许可证。

- **发布路径。** 预测值调用 `presentValue()`：显式期按官方起始增速线性淡出到有效终值，再加 10 年有限终值期和延续价值，与 `policy.js` 的所有者模型发布路径相同。折现是 `max(10%, ceil(当地十年期)+6)`，终值增速 4%。折现与终值不随本样本或市价调整。
- **基数。** `earnings` 是 `toStock()` 的官方盈利基数（五年加权正常化，或确认持续台阶时的最近三年加权值）；`cash` 是三年正的税后资本开支后现金中位数（或现金路径确认台阶时的最近三年中位数）；`midpoint` 是两边都为正时的算术中点，只作因子，不自动等于发布基数；`officialSelected` 是 `blendOfficialBase()` 的结果：差距不到 50% 以盈利为主，50%–200% 取中点，超过约三倍拒绝。金融机构剩余收益路径不用现金中点。
- **增速。** `zero` 为起点 0%（发布路径仍淡出到 4% 终值）；`five` / `ten` 是五年、十年盈利窗经 0% 下限与 15% 上限裁剪后的值；`slower` 是 `officialGrowth()`（两窗都在时取较慢者）。
- **怎么读表。** 同一行比较同一基数下的不同增速；同一列比较同一增速下的不同基数。不要再把「慢窗 + 五年盈利中位数」和「零增长 + 三年现金中位数」放在同一张主表里当作增速比较。
- **事后对照。** 可实现现金：入场后十年的税后资本开支后每股现金，按同一折现折现，再从最后一年观察值接上与发布路径相同的有限终值期和延续价值。业主盈利：同一套评分用在入场后的每股收益上（在 M≈D 假设下 OE=E）。2006 年调试面板目前只有现金结果、没有入场后盈利，故业主盈利目标在该集上暂缺。

冻结的 2006-03-15 五名美股（通用电气、UPS、波音、英特尔、IBM；威瑞森没有完整现金路径）只是 **调试集**，用来把 harness 跑通和复现拆分，不是对通用算法的验收。击败零增长不是发布门禁。

### 调试集上的现行发布路径结果（对可实现现金）

官方选定基数下，发布路径的中位 SMAPE：零增长 49.02%，五年窗 50.89%，十年窗 29.92%，慢窗 50.89%。本集五家的慢窗都是五年窗，所以五年列与慢窗列中位数相同。这只是调试集，不能写成通用结论；扩大样本状态为 `blocked`、已提交面板 0 个，因此不得据此宣称官方规则更准。

完整因子中位数（对可实现现金）：

| 基数 | 零增长 | 五年窗 | 十年窗 | 慢窗 |
| --- | ---: | ---: | ---: | ---: |
| 盈利 | 49.02% | 50.89% | 55.25% | 50.89% |
| 现金 | 43.95% | 43.44% | 27.03% | 43.44% |
| 中点（因子） | 39.86% | 55.08% | 29.50% | 55.08% |
| 官方选定 | 49.02% | 50.89% | 29.92% | 50.89% |

英特尔仍能说明「不要混基数」：盈利基数 0.85、现金基数 1.4284，官方选定取中点 1.1392；两边增速都是 0% 时，退役 Gordon 口径下误差 76.69%（盈利中位数）对 28.71%（现金中位数），差距全部来自基数。现行发布路径上，同一家官方选定 0% 与现金 0% 仍然不同，同样是基数差异。

## 退役口径：不要与现行主表混读

- `scripts/research/forecast-validation-research-2006.json` 是 2026-11-22 在研究分支口径下记录的历史跑数：朴素十年 CAGR、5/10/1 混合增速、写死的 11% 折现、不含终值。样本 4 家（通用电气、UPS、英特尔、IBM）。中位误差：零增长 14.83%，折半混合 26.02%，混合 29.995%，历史外推 37.52%。这不是官方 v3 结果。当时的 11% 恰好等于 `ceil(4.73) + 6`，但历史模式必须保持写死的 11%，以免被后来的官方口径改动带偏。
- `scripts/research/forecast-validation-official-legacy-gordon-2006.json` 冻结了旧官方文件：显式期用恒定增速，再一次性加上戈登终值，并且主表把五年盈利中位数 + 慢窗（76.69%）和三年现金中位数 + 零增长（43.97%）放在一起。那不是增速比较。新官方结果里的 `legacyConstantGordon` 仍可复现该拆分：固定五年盈利中位数时，长窗 57.38%、慢窗 76.69%；按当前基数选择与现金中点做该旧评分的静态近似时，长窗 42.14%、慢窗 50.42%、同基数零增长 50.42%。结论会随基数定义翻转。更早官方列含终值、对照列尚未对齐时约 71.68%，或不含终值时约 49.75%，都不要再当作现行口径。

## 扩大样本

扩大结果必须单独标注，不能把调试五家的输赢写成通用验收。诚实的扩大需要：入场日就固定的样本宇宙（不是今天的存活者回填）、只用当时已披露字段做预测（申报日与期间截止日过滤，禁止前视）、以及随后十年的现金和盈利结果。

本仓库目前还没有这样的冻结面板：没有可用的带日期 SEC 事实缓存，也没有 2006 调试集以外、同时含入场后现金与盈利的 walk-forward 面板。2006 调试集本身也还缺入场后每股收益，所以业主盈利目标还不能在该集上计分。希望覆盖的方向包括更晚的入场日期、A/H、平台与周期生意。

把符合上述约束的 JSON 面板放入 `scripts/research/forecast-validation-panels/`，再跑 `npm run research:forecast`。扩不出时不要硬凑有偏样本。

## 不会改什么

本工具不改 `POLICY_V1`、政策哈希、`calGr2fv`，也不重算或覆盖 `public/data/intrinsic/v3.json`。门禁只检查重算结果与已提交文件一致，不要求某种增速规则击败零增长基准，也不为贴近市价或调试集输赢调整折现或终值。
