# 预测检验工具

这是给维护者复核口径用的内部工具，不是面向普通投资者的功能，也不构成改官方增速或折现率的许可证。不要把它做成站点上的研究工作台，也不要把结果当作官方发布值。不要把检验数字或「领先 / 不领先」写进产品文案。

## 怎么跑

在仓库根目录：

```bash
npm run research:forecast            # 跑冻结面板，写入 scripts/research/forecast-validation-official.json
npm run research:forecast -- --check # 核对已提交官方结果
npm run research:forecast -- --historical
npm run research:forecast -- --historical --check
```

`npm run research:check` 包含官方与历史结果的 `--check`。默认输入是已冻结的 2006-03-15 入场现金面板 `scripts/research/cash-path-inputs.json`。扩大样本的面板放在 `scripts/research/forecast-validation-panels/`，输出一律放在 `scripts/research/`，不进入 `public/`，也不会出现在方法页。

## 现行官方检验：与发布路径对齐的因子实验

`scripts/research/forecast-validation-official.json` 是维护者因子实验，不是通用验收，也不是改官方规则的许可证。

- **发布路径。** 预测值调用 `presentValue()`：显式期按官方起始增速线性淡出到有效终值，再加 10 年有限终值期和延续价值，与 `policy.js` 的所有者模型发布路径相同。折现是 `max(10%, ceil(当地十年期)+6)`，终值增速 4%。折现与终值不随本样本或市价调整。
- **基数。** `earnings` 是 `toStock()` 的官方盈利基数（五年加权正常化，或确认持续台阶时的最近三年加权值）；`cash` 是三年正的税后资本开支后现金中位数（或现金路径确认台阶时的最近三年中位数）；`midpoint` 是两边都为正时的算术中点，只作因子，不自动等于发布基数；`officialSelected` 是 `blendOfficialBase()` 的结果：差距不到 50% 以盈利为主，50%–200% 取中点，超过约三倍拒绝。金融机构剩余收益路径不用现金中点。
- **增速。** `zero` 为起点 0%（发布路径仍淡出到 4% 终值）；`five` / `ten` 是五年、十年盈利窗经 0% 下限与 15% 上限裁剪后的值；`slower` 是 `officialGrowth()`（两窗都在时取较慢者）。留存硬约束在扩展面板的正式 `prediction` 路径由 `policyValue()` 计算；因子表的 `slower` 仍只是两窗诊断，不要混为留存绑定后的发布增速。
- **怎么读表。** 同一行比较同一基数下的不同增速；同一列比较同一增速下的不同基数。不要再把「慢窗 + 五年盈利中位数」和「零增长 + 三年现金中位数」放在同一张主表里当作增速比较。
- **事后对照。** 可实现现金：入场后十年的税后资本开支后每股现金，按同一折现折现，再从最后一年观察值接上与发布路径相同的有限终值期和延续价值。业主盈利：同一套评分用在入场后的每股收益上（在 M≈D 假设下 OE=E）。2006 年调试面板目前只有现金结果、没有入场后盈利，故业主盈利目标在该集上暂缺。事后十年之后仍由同一模型外推，因此对照值也不是已实现的全生命周期现金。

冻结的 2006-03-15 六名美股（通用电气、UPS、波音、英特尔、IBM、威瑞森）只是 **调试集**。威瑞森因 2006 拆分且没有完整现金路径被排除，实际现金评分五家；它不是对通用算法的验收，击败零增长也不是发布门禁。

### 调试集上的现行发布路径结果（对可实现现金）

| 指标 | 官方增速规则 | 同基数零增长对照 |
| --- | ---: | ---: |
| 中位 SMAPE | 51.8355% | 36.4910% |
| nearest-rank p90 SMAPE | 69.0108% | 84.4364% |
| 区间覆盖率 | 40%（5 家中 2 家） | — |
| 拒绝出值率 | 0%（0/5 eligible） | — |

同基数逐家比较的 SMAPE 差值（官方减零增长）：中位 -6.713 个百分点，p90 +15.3445 个百分点；官方较好 3 家、较差 1 家、持平 1 家。官方规则在这五家里没有稳定胜过简单基准，尤其不能把中位数优势解释成通用精度。五家全部来自同一入场年份、同一现金确认回退路径，不能据此断言全市场平均误差是 51.84%。

**40% 覆盖率是这五次事后实现值落入假设情景包络的频率，不是 40% 置信水平，也不是统计置信区间。** 拒绝率分母也不能掩盖缺失数据：本集五家都可评分，业主盈利五家全部因缺事后结果而 blocked，无法计算误差或覆盖率。

| 基数 | 零增长 | 五年窗 | 十年窗 | 慢窗 |
| --- | ---: | ---: | ---: | ---: |
| 盈利 | 36.4910% | 51.8355% | 35.9117% | 51.8355% |
| 现金 | 43.9535% | 43.4394% | 27.0336% | 43.4394% |
| 中点（因子） | 40.3331% | 55.5436% | 26.0406% | 55.5436% |

英特尔仍能说明「不要混基数」：当前官方盈利基数 1.4、现金基数 1.4284，二者只差 2.03%，官方选定为盈利侧 1.4，不是旧口径的中点 1.1392。差异必须按同一家公司、同一基数和同一事后目标比较。

## 退役口径：不要与现行主表混读

- `scripts/research/forecast-validation-research-2006.json` 是 2026-11-22 在研究分支口径下记录的历史跑数：朴素十年 CAGR、5/10/1 混合增速、写死的 11% 折现、不含终值。样本 4 家（通用电气、UPS、英特尔、IBM）。中位误差：零增长 14.83%，折半混合 26.02%，混合 29.995%，历史外推 37.52%。这不是官方 v3 结果。当时的 11% 恰好等于 `ceil(4.73) + 6`，但历史模式必须保持写死的 11%，以免被后来的官方口径改动带偏。
- `scripts/research/forecast-validation-official-legacy-gordon-2006.json` 冻结了旧官方文件：显式期用恒定增速，再一次性加上戈登终值，并且主表把五年盈利中位数 + 慢窗（76.69%）和三年现金中位数 + 零增长（43.97%）放在一起。那不是增速比较。新官方结果里的 `legacyConstantGordon` 仍可复现该拆分：固定五年盈利中位数时，长窗 57.38%、慢窗 76.69%；按当前基数选择与现金中点做该旧评分的静态近似时，长窗 55.45%、慢窗 51.64%、同基数零增长 43.97%。结论会随基数定义翻转。更早官方列含终值、对照列尚未对齐时约 71.68%，或不含终值时约 49.75%，都不要再当作现行口径。

## 扩大样本：当前 blocked

扩大结果必须单独标注，不能把调试样本的输赢写成通用验收。诚实的扩大需要：入场日就固定的样本宇宙（不是今天的存活者回填）、只用当时已披露字段做预测（申报日与期间截止日过滤，禁止前视）、以及随后十年的现金和盈利结果。

本仓库目前没有真实扩大面板：`forecast-validation-panels/` 已提交 JSON 为 0 个，没有带日期的 SEC as-of 事实缓存，也没有 2006 调试集以外同时含入场后现金与盈利的 walk-forward 面板。因此扩大状态必须是 `blocked`，组合、跨年份和分行业结果保持空值，不能以合成数据替代真实历史验收。2006 调试集本身也缺入场后每股收益，业主盈利还不能在该集上计分。

### 冻结扩展面板契约

每个真实 JSON 面板必须包含：

- `asOf`、`yieldPct`、`universeFrozenAt`、`universeRule`，以及由 `panelUniverseHash()` 对排序后的 ticker/CIK/industry 成员清单计算的 `universeHash`。
- `companies[]` 的公司身份、行业、带日期的 `epsSeries`、`baseYears`、可选 `revenueChecks`，以及 `observations` / `cashObservations` 和 `epsObservations`。
- 每条事实的 `fy`、`periodEnd`、`availableAt`、`source`；现金行还需有限 `ocf`、`capex` 和正 `shares`，盈利行需有限 `val`（入场）或 `eps`（结果）。null、undefined 和空串不是零，必须拒绝。
- 现金与盈利结果各恰好十个财年，并严格对应最新可见入场 EPS 财年的 FY+1…FY+10。

`npm run research:forecast` 会拒绝缺日期、冻结日过期、成员哈希不符和错误结果年份的面板，并把期间截止日或披露日晚于 asOf 的事实从入场输入中过滤。汇总同时报告 eligible、refused、entry/outcome blocked、scored；分组按 `entryYear` 与 `industry` 输出。中位误差、nearest-rank p90、区间覆盖率、两种拒绝率分母和同基数零增长比较均只对有真实结果的行计算。

当前扩展评分入口仍固定 NYSE/USD 每股口径；**不能宣称真实 A/H walk-forward 已受支持**。要纳入 A/H，必须先补上市地、申报币种、报价币种和每股汇率的显式契约，再用真实冻结面板验证，而不是把本地币数字直接标成美元。

## 不会改什么

本工具不改 `POLICY_V1`、政策哈希、`calGr2fv`，也不重算或覆盖 `public/data/intrinsic/v3.json`。门禁只检查重算结果与已提交文件一致，不要求某种增速规则击败零增长基准，也不为贴近市价或调试集输赢调整折现或终值。
